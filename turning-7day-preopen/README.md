# 开盘前、7 个交易日、一对一、双 80 验收口径

用户已确认开盘前发出警报，只使用当时已公布的数据。本项目沿用现有 09:20（北京时间）研究决策时钟；09:20 是已有基线的取值，并非用户另行指定的分钟。

验收目标：5% 顶、5% 底、9% 顶、9% 底分别达到警报精确率 ≥80%、实际拐点覆盖率 ≥80%。这是一项目标，不代表已实现或必然可实现。

## 固定规则

警报 D 日之后第 1 至第 7 个实际交易观察日内，出现相同尺度、相同方向的真实拐点才算命中。D 当天及第 8 日不算。窗口按交易日位置计算，不按自然日。当前数据的交易日期集合属于归档观察集合，未独立完成所有交易日历认证。

一个正式警报最多匹配一个拐点，一个拐点最多匹配一个正式警报。各任务独立配对，不用 5% 顶替代 9% 顶，不用底替代顶。采用预先固定、确定性的一对一最大数量匹配，匹配数量相同时固定按时间和 ID 排序，不能根据收益任意挑选。

精确率 = 命中的正式警报 /（命中警报 + 误报警报）。

覆盖率 = 收到提前警报的成熟拐点 /（收到提前警报的成熟拐点 + 漏判拐点）。

同一拐点前多发的正式警报不能重复记命中；每日状态刷新不冒充新警报。警报一经发出不得事后撤回以删去误报。没有足够未来观察的记录保留 PENDING 并单列数量。没有警报或没有目标的分母为空时，结果为未定义，不判通过。

顶底客观标签沿用冻结的 5% / 9% 收盘反转拐点。匹配拐点实际日期，不匹配之后的确认日期；确认日期仅用于确定标签何时可用于训练和评分。标签不得反向进入当日信号。用户目前没有另行要求正式警报必须顶底交替，因此不擅自通过强制交替删除已经发出的同方向警报。

开盘前 D 日的收盘、全天成交额、全天换手等均未知。D-1 或更早的数据也要核对实际发布时刻不晚于决策时刻，单纯把时间序列移一天不能证明可用。训练、验证边界需要隔离重叠结果窗口和尚未确认的标签。

## 现有基线按新窗口重评

对象是仓库 V101 固定价格规则，不是将收盘后六因子模型直接挪到开盘前。数据为 2022-02-23 至 2026-10-20，1128 个观察日。参数、冷却期、原始警报日期和客观标签均不变，只把旧 10/20 日评分窗口改为 7 日。

保留原基线的确认后 140 个观察日成熟缓冲，不因本次成绩改变。两端未成熟记录保留，初期缺乏足够历史的成熟漏判仍计入主口径，没有为了提高覆盖率临时删除。

|任务|命中|误报|漏判|待定警报|精确率|覆盖率|
|---|---:|---:|---:|---:|---:|---:|
|5% 顶|8|11|8|2|42.1%|50.0%|
|5% 底|4|14|12|4|22.2%|25.0%|
|9% 顶|2|7|5|1|22.2%|28.6%|

四项均不达标。样本是反复研究过的历史，且历史发布时点未认证，所以这里只能称为回顾性研究基线，不能称为实际历史开盘前预测成绩或独立样本外效果。

## 已明确的差距

5% 底的两条原命中都提前 8 日，改为 7 日后变成误报：2023-10-11 → 2023-10-23；2024-09-03 → 2024-09-13。

9% 底的两条原命中分别提前 12 和 19 日：2024-01-18 → 2024-02-05；2024-08-19 → 2024-09-13。新标准下都不是命中。

这些记录支持优先检查底部信号的触发时机，但不能把所有误报都解释成提前过早。下一步把误报拆成过早、方向无对应拐点、重复警报，把漏判拆成规则未触发、冷却抑制、历史不足，再据此设计候选。高低位候选状态与正式警报可分开研究，只有正式警报进入精确率分母；候选状态必须按事先固定规则转换，不能事后选命中的才叫正式。

任何新规则先冻结，再在后续真实首次捕获的数据上验证；不反复修改标签、窗口和分母把已看过的历史拟合到双 80。正式验收应同时披露样本数、不确定性和样本独立性。

## 可核验文件与数据流

冻结价格 → D-1 及更早特征 → 未改参数的 V101 FORMAL_START → 同尺度同方向、提前 1—7 交易日匹配 → 精确率 / 覆盖率。事后拐点仅进入匹配评分。

- evaluation_contract.json：机器可读验收口径。
- baseline_7day.json：来源 SHA256、真实分子分母和限制。
- alert_to_pivot_7day.csv：59 条警报的命中、误报和待定明细。
- pivot_to_alert_7day.csv：全部拐点的命中、漏判、边界和待定明细。
- lost_hits_after_7day_change.json：窗口缩短后失去命中的四条警报。
- inputs/：从 Git 原始对象读取、字节哈希与冻结源一致的价格和标签。
- evaluate_baseline.py：复用 V101 生成器和 V102 独立动态规划匹配，另用 V101 贪心匹配核对最优匹配数量。
- test_evaluation.py：已运行 5 项测试，覆盖第 0/1/7/8 日边界、重复匹配、250 组穷举对照、未来价格污染、真实记录守恒。
