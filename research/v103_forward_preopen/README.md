# V103｜未来开盘前原始价格首次观测

**研究状态：原版代码已部署，原版9项模拟测试云端通过；首次有效定时真实采集尚未核验。** 本阶段不追溯旧预警，不更改V101/V102的冻结规则、历史成绩或正式网页。

## 解决什么问题

V101将D-1收盘价视为D日09:20前已知，但2022—2026归档价格缺少逐日真实首次公布时间。历史回放即使没有用D日收盘，也不能证明当年盘前真的能看到D-1数据。

V103从未来开始，直接在每个工作日北京时间09:10向中证指数官方`000985`历史指数端点请求原始响应。记录请求开始、响应完成的UTC时间、原始响应字节及SHA256。只有**整个请求在09:20前完成**，官方返回指数代码一致、没有D日及未来收盘、至少127个有效历史交易日、最近一个观测日等于前一个工作日，才标记为`PASS_PREOPEN_RAW_SOURCE_OBSERVED_RESEARCH_ONLY`。其他情况一律记录`BLOCKED`，不填充缺失值。

即使来源通过，这也只能证明**我们的采集程序在该时间看到了这些数据**。它不证明发布方最初何时发布，不证明交易日历已获官方认证，不证明历史每一天同样可获取，更不代表模型胜率提升。原始响应包含异常周末行时单独隔离并记录，不能把周末算成真实交易日。

## 交付内容

- `first_capture.py`：官方源直接采集、09:20截止检查、原始SHA、逐日首次观测不可覆盖。仅标准库依赖。
- `test_first_capture.py`：9项独立模拟测试，覆盖盘前成功、跨截止线、盘前过早、错误指数、D日未来数据、来源过期、回看不足、周末异常、网络失败、SHA不符和首次观测不可覆盖。
- `v103-forward-first-capture.yml`：可复制到`.github/workflows/`的研究工作流模板，工作日09:10（北京时间）采集，GitHub云端调度延迟则自动BLOCKED。测试在代码推送时执行，但代码推送**不会**误触发盘前采集。

## 使用和阻塞条件

```bash
python -m unittest discover -s research/v103_forward_preopen -p 'test_*.py' -v
python research/v103_forward_preopen/first_capture.py
```

第二条命令只应在未来交易日北京时间09:00—09:20之间运行；其他时间会生成一份`BLOCKED`记录。每个决策日只允许一份不可修改的`observations/YYYY-MM-DD/first_capture.json`；成功获取的原始响应保存在同目录`official_index_raw.json`。任何重复执行不覆盖首次观测。失败原因也留痕，不能事后删去失败样本。

**重要：** 工作流已存在于远端\`.github/workflows/\`，其定时配置是否成功获取真实盘前源需观察对应交易日的 schedule 运行。2026-10-22尚无确认的有效盘前数据，模型不产生FORMAL_START。正式信号始终`false`，生产状态不变。未来若要启用完整影子预测，还需独立认证交易日历、按真实前瞻日持续积累模型边缘状态和冷却状态，并在评分时只使用未来事后确认的标签。
