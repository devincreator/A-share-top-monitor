# 顶底判定口径审计

结论：当前实现对“5%/9%收盘反转拐点”这一数学定义自洽，但这不证明它就是用户希望预测的交易顶底。应先明确价格口径和警报当天计数，再继续优化。旧标签、旧评分和模型本轮均未修改。

## 当前定义

用中证全指日收盘价，价格从运行高点回落5%/9%确认顶部，从运行低点反弹相应幅度确认底部。标签记在先前收盘极值日期，另记录更晚的确认日期。初始左边界事件排除，末端未确认段不强行标注。

已用独立逐段搜索、Decimal精确价格重算：5%共135个已确认标签、9%共65个，标签日期、方向、确认日期均与现有算法一致。顶底交替和确认日期顺序检查通过。没有发现本次数据中相同收盘价择日歧义。这个核验只确认给定定义的重建一致性，不认证标签符合业务目标或历史开盘前可见性。

## 价格口径不同会产生不同顶底

在同一个收盘算法定义的波段区间中，比较盘中high/low极值日期与收盘极值日期，5%有85/135个不同，9%有40/65个不同。

这不表示85个或40个标签算错，也不是完整重建的盘中拐点序列。它说明“收盘极值”和“盘中极值”不是同一目标。真正按OHLC重建时，同一天的最高价和最低价先后顺序还可能无法仅凭日线确定，应保留歧义或使用更细数据。

## 警报时钟与目标日期存在业务疑点

现行合同明确只算警报后D+1至D+7，不计D当天。但警报在D日开盘前，D日收盘极值在警报之后发生，在真实时间上属于未来。旧价格规则的模拟研究警报中，发现4条同日拐点被当前口径判FP：

|任务|模拟警报日|收盘拐点日|
|---|---|---|
|5_BOTTOM|2017-05-23|2017-05-23|
|5_BOTTOM|2019-01-03|2019-01-03|
|9_TOP|2024-10-08|2024-10-08|
|9_BOTTOM|2019-01-03|2019-01-03|

是否改为D到D+6共7个交易日，属于业务定义选择，不应因为改完成绩更好才决定。若用户仍要求必须提前至少一个完整交易日，保留D+1到D+7也合理。本次没有改评分。

## 顶底日与确认日必须分开

5%标签确认滞后中位6个交易日，最长49日；9%中位16日，最长125日。分别有62个5%标签、53个9%标签确认滞后超过7日。

这与“警报后7日内出现拐点”并不矛盾：用户若预测的是极值日，确认可以发生更晚。但是如果实际要求7日内确认足够幅度的反转，就不是当前目标。不可混淆为标签计算错误，也不能在极值当天把事后确认标签当已知特征。

固定5%/9%也会随市场波动环境产生不同节奏。若用户要的是持续若干周的显著交易波段，须另行定义时间/幅度约束，不能按模型胜率事后选择。

## 建议的下一步

暂停新增参数搜索。先由用户明确收盘还是盘中、当天是否计入；再从预先选定的几段行情人工核对其直觉中的顶底与标签是否一致。冻结定义后，旧定义与新定义单独存档、独立重评，不把改标签产生的成绩变化说成预测能力提高。

如果只是不同定义下标签日期变化，不能据此证明模型有能力提前预测；若定义保持，模型失败仍需要继续分析。不能通过将警报后出现的任意小波动都称为顶底来提高命中率。
