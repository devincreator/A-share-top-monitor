# 当前唯一主动研发任务：真实历史预警重建、逐事件回测与误报归因

> 任务冻结：2026-10-21。**本阶段只做真实事件证据、回放时钟、事件匹配和误报归因。**
> V94融资精度扩展、V95股票池/C50扩展、V96联合因子、V98调参、V99影子部署、V100发布均暂缓主动研发。已存在的只读自动采集/归档维护工作流不自动变成新开发任务。正式生产网页/策略不修改。

## 0. 目标与最重要的因果约束

**目标**：获得可复现的每一次5%/9% TOP/BOTTOM正式预警事件，逐条解释TP/FP/FN、早报天数、所在市场环境及重复报警；最终形成基准与改进模型可公平比较的回测资料。

**预测决策发生在交易日D的开盘前，绝不能默认D日收盘价、成交额、换手率、融资余额、广度、C50已经可知。**

对每个因子f，精确使用如下合同：

```
decision_at = D日真实决策时刻（带 Asia/Shanghai 时区，且时间严格早于09:30）
source_observation_date(f) < D
original_publication_at(f) <= decision_at
source_data_sha256, source_uri, original_publication_proof_uri 均存在
```

* 观察日严格早于预测日：即使D当日尚有少量行情/API“回填”，也不能用于D日开盘前决策。
* D-1日数据**不天然可用**：若融资或市场广度直到D日09:40才公布，D日09:00预测必须进一步向前找已经公布的旧观测值，不能把D-1日金额当作已知。
* 如历史实际披露时间无法独立证明，只能标`BLOCKED_PIT`或`RESEARCH_SCHEMA_ONLY`，不能因历史文件存在或网页HTTP200就升格。
* 对D日预测做市场趋势/熊市反弹归因，只准用D-1及之前的收盘行情；`research/v86_event_models/event_audit.py`已修正原本错误引用D日收盘的描述性归因。
* 拐点客观标签可在之后确认，但永远只用于事后评分，不能作为D日的模型输入、特征、波段阶段或提前知晓的标签。
* 历史价格的“D-1之后普遍可获得”可用于明确标识的研究假设，但不等于当时有独立时点认证；正式G1不得靠假设通过。
* 如没有某个模块的数据，必须明确它在当时`NOT_AVAILABLE`，禁止默认置0、插值、用事后报表替代；旧策略实际用了多少模块需要源码或原始报警审计证明，不可猜测。

## 2. 固定任务合同

* 四任务独立：`5_TOP`、`5_BOTTOM`、`9_TOP`、`9_BOTTOM`；预警目标精确率≥80%、成熟客观拐点覆盖率≥80%，**四项分别**计算。
* 5%正式事件需比对应真实拐点提前1—10个完整交易日，9%提前1—20日；不许同日高低点算提前预警。
* 报警`FORMAL_START`才计一条；`ACTIVE`、每日强化、撤销和状态重发不重复计入报警次数。
* 一条报警最多对一个成熟标签，一个成熟标签最多匹配一条报警，按严格交易日序列做最大一对一匹配。
* 标签独立冻结：中证全指主轨道按V52交替ZigZag确认日；沪深300长期轨道仍须按LONG_CSI300原始标签代码与原始价格源重放，不混用。
* 不成熟客观标签和末端正式报警必须分别保持`PENDING`；要求140交易日训练隔离及至少140交易日的末端标签成熟缓冲；有确认日期的标签仍须通过源完整性审计。
* 新旧策略对照必须同日历、同指数、同可观测时刻、同成熟事件集合、同年度报警预算。先核对旧策略是否开盘前可执行，若它用D收盘计算，不把原始成绩直接搬成D开盘前基准。
* 2012—2014为旧开发期、2015—2021为旧迁移检验、2022—2026已反复探索，严禁将后三者称为新的真实未见过的前瞻样本。2026冻结以后首次实际产生的独立预测才可用作前瞻。

## 3. 严格串行的四个子任务与通过标准

### E1 — 真实事件证据恢复（当前首要阻塞）

寻找原始V63—V68 ZIP、当年运行日志、独立已有事件CSV及不可变模型源码版本。先提供`alerts.csv`、`pivots.csv`、`prices.csv`及带SHA256/指数代码/标签版本的`manifest.json`。如重新执行现有可信旧源码重放，必须标`NEW_DETERMINISTIC_REPLAY`，不可称作当时原始报警档案。

**PASS**：每行事件来源可追溯，完整哈希，正式报警/成熟标签与价格日期匹配，旧聚合报告中能够复核的口径独立复核；若无法比对，明示差异；原ZIP缺失则`BLOCKED_ORIGINAL_SOURCE`。

### E2 — 开盘前信息截点复原（E1之后）

以`research/v97_event_intake/preopen_clock.py`对每一次D日开盘前决策的每个因子检查`observation_date < D`与`published_at <= decision_at`，缺原始披露时点/可信源证据即阻塞。含未来同日数值的旧日报/模型不能当作同一时刻的前瞻信号。

**PASS**：该评价事件集的决策时刻/当时可用历史因子逐条取数均有来源证明；任何同日因子、公布过晚、时间戳无时区及未知披露时间都不能通过。

### E3 — 成熟事件一对一回测与错误归因（E2之后）

以`preopen_event_audit.py`进行真实事件一对一匹配；未过末端成熟窗或不完整的标签维持`PENDING`，不计算FP或FN。每日阶段特征严格截至D-1。对已成熟事件输出TP/FP/FN、正式报警数量、覆盖、精确率、完整底→顶→底循环和对应市场阶段。主轨道/长期轨道分离输出。

**PASS**：全事件可追溯重算，逐事件与统计一致，模型时钟和标签成熟可审计，未成熟不罚；每条被记为错误的报警有触发事实与原始来源。

### E4 — 严格新旧模型可比性诊断（E3之后）

只做描述性误报归因和前后可比分析，**先不调参**。错误类型包括长期下跌反弹顶部、上涨趋势误判、震荡噪声、报警过早/过晚、融资未公布、重复报警与标签尚未成熟。需要逐事件原始证据，不能从49次误报的聚合数量逆推出分类比例。

**PASS**：四任务分年度分阶段原始TP/FP/FN、导致错误的因素、可执行的改进假设均有事件级原始证据。E4通过后才讨论正式参数试验，不为了回填旧成绩而调阈值。
